# Close-Reading Academic Notes

一个面向 **Codex 与兼容 Agent Skills 规范的智能体** 的可复用学术阅读 Skill，用于对文学、语言学、翻译学、历史学、哲学、社会学及相邻人文社会科学文献进行证据驱动的深度阅读、论证重构与批判性评估。

它适合处理：

- 学术论文与书评；
- 专著及逐章阅读；
- 论文集中的单篇章节；
- 文献综述与研究卡片；
- 需要文本细读、概念谱系、理论脉络或证据审计的研究材料。

该 Skill 的目标不是简单总结“作者说了什么”，而是进一步回答：

1. 作者究竟试图解决什么问题？
2. 核心结论是如何一步步推导出来的？
3. 每个关键主张由什么证据支撑？
4. 从证据到结论之间是否存在缺失的推理环节？
5. 作者继承、修正或挑战了哪些理论传统？
6. 这篇文献可以如何转化为论文写作与后续研究可调用的知识资产？

## 核心特点

### 1. 证据优先

所有分析原则上都应回到原始文本，不使用“听起来合理”的学术常识填补材料空白。无法确认的内容统一标记为 `[待核]`。

### 2. 区分作者观点与分析者判断

Skill 使用五类认识论标签：

- `[明示]`：作者在文本中直接表达或明确引用；
- `[归纳]`：根据文本多处内容概括得出；
- `[推断]`：分析者依据论证结构作出的合理解释；
- `[延伸]`：超出本文范围的跨学科联想或研究应用；
- `[待核]`：材料缺失、文字不清或尚未验证。

这可以降低理论强贴、作者立场误归属和模型幻觉。

### 3. 重构论证，而非复述目录

核心分析单位是：

```text
主张 → 证据 → 推理依据 → 阶段性结论 → 遗留问题
```

它可以帮助识别：

- 论证跳跃；
- 证据不足；
- 个案过度推广；
- 相关关系与因果关系混淆；
- 概念在论证过程中发生漂移；
- 作者未处理的重要反例。

### 4. 严格核验引文与页码

- 只摘录材料中真实存在的原文；
- 不把概述或改写放入引号；
- 保留外文原文；
- 自行翻译时明确标注“自译”；
- 页码无法确认时标注 `[页码待核]`；
- 宁可少摘，也不生成拟似引文。

### 5. 适配论文、章节、专著与快速卡片

Skill 内置四种分析模式：

| 模式 | 适用对象 | 分析重点 |
|---|---|---|
| `paper` | 论文、书评、独立文章 | 研究问题、论证链、方法、证据、贡献与局限 |
| `chapter` | 专著或论文集章节 | 章节功能、前后章关系、本章对全书命题的贡献 |
| `book` | 完整专著或论文集 | 全书结构地图、逐章笔记、概念演变与总体综合 |
| `quick` | 快速阅读或文献初筛 | 一页式研究卡片与核心判断 |

## 目录结构

```text
close-reading-academic-notes/
├── SKILL.md
├── README.md
├── references/
│   ├── output-template.md
│   └── quality-checklist.md
└── tests/
    └── scenarios.md
```

各文件作用如下：

- `SKILL.md`：Skill 的触发条件、核心原则、工作流与模式要求；
- `references/output-template.md`：完整学术笔记输出模板；
- `references/quality-checklist.md`：输出前的真实性与质量审计清单；
- `tests/scenarios.md`：用于验证 Skill 是否能够抵抗常见错误的压力测试场景；
- `README.md`：安装、调用与维护说明。

## 安装到 Codex

### 方法一：安装到跨运行时 Skills 目录

将整个仓库复制到：

```text
~/.agents/skills/close-reading-academic-notes/
```

macOS、Linux 或 WSL 中可以执行：

```bash
mkdir -p ~/.agents/skills
git clone https://github.com/manoloss612/close-reading-academic-notes.git \
  ~/.agents/skills/close-reading-academic-notes
```

安装完成后，核心文件应位于：

```text
~/.agents/skills/close-reading-academic-notes/SKILL.md
```

重新启动 Codex 会话，使 Skill 被重新发现。

### 方法二：安装到项目内部

需要随项目共同维护时，也可以将本仓库复制到项目约定的 Skills 目录中。应确保 Agent 能够发现并读取 `SKILL.md`。

## 使用方法

通常不需要输入固定命令。只要任务与学术文献深度阅读相关，Codex 即可根据 `SKILL.md` 的描述识别并加载本 Skill。为了提高确定性，也可以在指令中明确指定 Skill 名称和分析模式。

### 示例一：分析学术论文

```text
请使用 close-reading-academic-notes skill 阅读这篇论文，
采用 paper 模式生成完整学术笔记。
所有关键判断都要回到原文，重要引文保留原文并标注页码。
```

### 示例二：分析专著章节

```text
请使用 close-reading-academic-notes skill 分析本章，采用 chapter 模式。
除了本章核心论证，还要说明本章在全书中的功能、与前后章的关系，
以及它对全书中心命题的贡献。
```

### 示例三：逐章分析整本专著

```text
请使用 close-reading-academic-notes skill 分析这本专著，采用 book 模式。

先建立全书问题与结构地图，再逐章生成独立 Markdown 笔记，
最后回到全书层面，评估各章是否共同支撑作者的总体命题。
每章笔记完成后保存为单独文件。
```

### 示例四：生成一页式文献卡片

```text
请使用 close-reading-academic-notes skill 的 quick 模式，
将这篇论文整理为一页式研究卡片，重点保留核心问题、三步论证链、
关键概念、最强证据、主要贡献、最大局限和研究相关性。
```

### 示例五：批量分析多篇文献

```text
请对当前目录中的所有学术 PDF 使用 close-reading-academic-notes skill。

要求：
1. 自动判断使用 paper 或 chapter 模式；
2. 每篇文献生成一份独立 Markdown 笔记；
3. 无法确认的信息标记为 [待核]；
4. 不得虚构作者观点、引文或页码；
5. 最后生成 synthesis-matrix.md，比较所有文献的核心问题、
   理论框架、材料、方法、贡献、局限及相互关系。
```

## 标准输出结构

完整模式通常包含以下模块：

1. 阅读范围与分析状态；
2. 元数据；
3. 文献定位与章节功能；
4. 核心命题与问题化方式；
5. 论证逻辑树；
6. 主张—证据—推理矩阵；
7. 理论装置与概念地图；
8. 文本互涉与学术谱系；
9. 证据解剖；
10. 重要引文；
11. 批判性评估；
12. 研究启示与可复用研究资产；
13. 一页式总结。

具体字段与格式见 [`references/output-template.md`](references/output-template.md)。

## 推荐工作流

### 论文

```text
确认材料完整性
→ 提取元数据
→ 定位研究问题
→ 建立证据台账
→ 重构论证链
→ 分析理论与学术脉络
→ 核验引文
→ 批判性审计
→ 输出研究卡片
```

### 专著

```text
确认全书材料
→ 阅读目录、导论与结论
→ 建立全书结构地图
→ 逐章分析
→ 追踪核心概念的变化
→ 比较章节之间的功能
→ 回到全书总体命题
→ 评估全书结构是否真正支撑结论
```

处理长篇专著时，建议分阶段保存结果，避免一次生成过长输出，也便于后续修订和交叉比较。

## 质量保障

交付笔记之前，应执行 [`references/quality-checklist.md`](references/quality-checklist.md) 中的检查，至少确认：

- 是否准确说明了实际阅读范围；
- 是否把摘要或作者自述误当成已经证明的结论；
- 是否区分作者观点、文本归纳和分析者推断；
- 是否存在没有文本依据的理论标签；
- 是否逐字核验了引文；
- 是否核验了页码；
- 是否把章节目录复述误当成论证重构；
- 是否说明了证据与结论之间的推理依据；
- 是否对批评判断给出了文本依据和置信度；
- 是否避免机械套用性别、阶级、种族或技术等批判维度。

`tests/scenarios.md` 提供了典型压力场景，可用于测试不同模型在加载与未加载 Skill 时的行为差异。

## 适用范围与限制

### 适合

- 人文社会科学论文精读；
- 理论专著逐章阅读；
- 文献综述准备；
- 概念史与思想谱系分析；
- 文学和哲学文本细读；
- 翻译学、语言学和社会科学研究笔记；
- 研究生课程阅读报告；
- 建立 Obsidian、Logseq 或 Markdown 知识库。

### 不适合直接替代

- 对无法访问的全文进行“整本书分析”；
- 在未核对原文的情况下生成精确引文；
- 代替专业版本学、档案学或语文学考证；
- 仅凭标题、摘要或书评推断整部著作；
- 将模型生成的批判性判断当成无需复核的最终学术结论。

## 自定义

可以根据个人研究习惯修改：

- `references/output-template.md`：增删笔记模块或调整字段；
- `references/quality-checklist.md`：添加学科专属检查项；
- `tests/scenarios.md`：加入自己常见的文献类型和失败案例；
- `SKILL.md`：调整触发条件、默认模式和认识论标签。

例如，翻译学研究可以增加“原文—译文—翻译策略—规范约束”矩阵；文学研究可以增加“叙述视角—修辞结构—意象系统—历史语境”；思想史研究可以增加“概念来源—语义迁移—历史断裂—接受路径”。

---

## 维护建议

修改 Skill 时，建议遵循以下顺序：

1. 在 `tests/scenarios.md` 中加入一个能够暴露问题的测试场景；
2. 观察 Agent 在没有新规则时如何失败；
3. 修改 `SKILL.md` 或参考文件；
4. 使用同一场景重新测试；
5. 检查新规则是否造成输出冗余或新的误判。

这种方式可以让 Skill 在长期使用中逐渐形成稳定、可验证的研究工作流。
